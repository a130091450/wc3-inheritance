# 属性系统设计（v1.1）

> 魔兽3 自定义地图《无尽刷怪》· 属性系统
> 架构：**血量完全自管（基础血量 + 属性血量），其余属性交给引擎原生常数**

## 一、设计目标

1. 血量按自定义公式算：`基础血量 + 属性血量`
2. 其他属性（魔法、回血、回蓝、护甲、攻速、攻击）尽量用引擎原生常数
3. 装备等"直接加血"的来源记为「基础血量」，与属性换算互不干扰
4. 本期只实现**血量**一条链，其余属性留到后续

## 二、架构总览

| 属性关系 | 由谁负责 | 实现 |
|---|---|---|
| **血量（最大生命）** | **触发器自管** | `基础血量 + 属性血量`，见第六节 |
| 力量 → 生命回复 | 引擎 | 常数 `StrRegenBonus` = 0.01 |
| 智力 → 魔法 | 引擎 | 常数 `IntManaBonus` = 1 |
| 智力 → 魔法回复 | 引擎 | 常数 `IntRegenBonus` = 0.01 |
| 敏捷 → 护甲 | 引擎（关闭） | 常数 `AgiDefenseBonus` = 0 |
| 敏捷 → 攻速 | 引擎（关闭） | 常数 `AgiAttackSpeedBonus` = 0 |
| 主属性 → 攻击 | 引擎 | 原生 1:1（力量型受 `StrAttackBonus` 控制） |

> **血量为什么自管**：敏捷加生命、智力加生命在引擎里**没有对应常数**，只能自己算。
> 既然要自己算，就索性把"力量×2"也纳入同一公式，保证三个属性统一由一张表换算。

## 三、血量公式（核心）

```
最大生命 = 基础血量 + 属性血量

基础血量 = 单位模板血(0) + 装备/技能/书 直接加的数值
属性血量 = 力量×2 + 敏捷×1 + 智力×0.5
```

| 项 | 初始值 | 说明 |
|---|---|---|
| 基础血量 BaseHP | **0** | 不读模板基线；装备/书直接加的数值累加到这里 |
| 属性血量 AttrHP | 由属性算 | 力量 10 → 20，敏捷 10 → 10，智力 10 → 5（初始 35） |

### 3.1 换算系数（定稿）

| 来源 | 目标 | 系数 |
|---|---|---|
| 力量 | 血量 | **×2** |
| 敏捷 | 血量 | **×1** |
| 智力 | 血量 | **×0.5** |

## 四、游戏常数改动清单（6 项）

通过改地图 `misc.ini`（解包 → 改 → `w2l obj` 打包），或编辑器「游戏平衡性常数」界面。

| 常数 | 默认 | 改成 | 原因 |
|---|---|---|---|
| **`StrHitPointBonus`** | 25 | **0** | **血量由触发器自管，引擎不参与** |
| `StrRegenBonus` | 0.05 | **0.01** | 力量每点 +0.01 回血 |
| `IntManaBonus` | 15 | **1** | 智力每点 +1 魔法 |
| `IntRegenBonus` | 0.05 | **0.01** | 智力每点 +0.01 回蓝 |
| `AgiDefenseBonus` | 0.30 | **0** | 敏捷不加护甲 |
| `AgiAttackSpeedBonus` | 0.02 | **0** | 敏捷不加攻速 |

> `StrAttackBonus` 保持 1.0（主属性→攻击 1:1，引擎原生白字）。

## 五、变量设计（本期只需血量相关）

```jass
// === 血量自管（必须）===
integer BaseHP[4]      基础血量（装备/技能/书 直接加的累加值，初始 0）
real    AttrHP[4]      属性血量（缓存，便于 UI 显示与调试）

// === 传参用 ===
unit    ModTarget      修改目标
real    ModDelta       血量增量（可负）

// === 内部临时 ===
integer TempInt        通用整数临时
real    TempReal       通用实数临时
```

> 蓝量/回血/回蓝/攻击等由引擎算，**本期不建对应变量**。

## 六、触发器设计（两个）

### 6.1 `Stat_Refresh` —— 写入血量（唯一执行 Set 的地方）

**触发**：被 `Stat_Mod` / 属性变化 / 升级 / 复活 / 1 秒周期调用

**入参**：`RfTarget`（unit）

**逻辑**：

```
// 0) 前置检查
if RfTarget == null then return
if IsUnitAliveBJ(RfTarget) == false then return

// 1) 取索引与属性
pid = GetPlayerId(GetOwningPlayer(RfTarget))
str = GetHeroStr(RfTarget, true)
agi = GetHeroAgi(RfTarget, true)
int = GetHeroInt(RfTarget, true)

// 2) 算属性血量（保留小数，写入前取整）
AttrHP[pid] = str*2 + agi*1 + int*0.5

// 3) 负数保护
if BaseHP[pid] < 0 then BaseHP[pid] = 0

// 4) 求最终值并四舍五入
newMax = R2I(BaseHP[pid] + AttrHP[pid] + 0.5)

// 5) 写入
SetUnitState(RfTarget, UNIT_STATE_MAX_LIFE, newMax)
if GetUnitState(RfTarget, UNIT_STATE_LIFE) > newMax then
    SetUnitState(RfTarget, UNIT_STATE_LIFE, newMax)   // 直接钳制
endif
```

**要点**：
- 只算血量，不碰魔法/回血/回蓝/攻击（那些引擎负责）
- 死亡单位不刷（复活时再刷）

### 6.2 `Stat_Mod` —— 改基础血量（装备/技能/书 的唯一入口）

**触发**：装备拾取/丢弃、技能、书、道具

**入参**：
| 变量 | 类型 | 含义 |
|---|---|---|
| `ModTarget` | unit | 目标单位 |
| `ModDelta` | real | 血量增量（可负） |

**逻辑**：
```
pid = GetPlayerId(GetOwningPlayer(ModTarget))
BaseHP[pid] = BaseHP[pid] + ModDelta
Stat_Refresh(ModTarget)
```

> **本期只有"血量"一个字段**，所以不需要 `ModField`。以后加"直接加蓝/回蓝"时再扩展。

**调用示例**：
| 场景 | ModDelta |
|---|---|
| 捡起「生命宝石 +300」 | +300 |
| 丢掉该装备 | -300 |
| 使用「生命之书 +100」 | +100 |

## 七、单位模板改动

| 单位 | 改动 | 原因 |
|---|---|---|
| `H000`（英雄） | **最大生命 = 0**、最大魔法 = 0、**力量/敏捷/智力 = 10/10/10** | 血量公式从 0 起算；属性初始值写物编，避免创建时跳变 |

> 属性写进物编（而非触发器 SetHeroStr），创建瞬间血量就是 35，无跳变。

### 8.3 实施注意

| 项 | 要求 |
|---|---|
| 文件位置 | 地图**根目录** `war3mapSkin.txt`（不是 `war3imported\`） |
| 编码 | 1.27 中文版用 **ANSI/GBK** |

## 九、幂等 / 性能 / 并发防护

### 9.1 前置检查（已写进 6.1）
- 判空（玩家离开后 `HeroP[pid]` 为 null）
- 存活检查（死亡不刷）

### 9.2 重入防护
- `Stat_Refresh` 内不注册/不触发任何会回调自身的事件
- 若将来监听"获得 buff"，加 `Refreshing[pid]` 标志位防递归

### 9.3 装备记账防重复（本期先立规矩）
- 装备数据带唯一标识（物品句柄 / 装备 ID）
- 记账前检查"是否已记账"（哈希表 `装备句柄 → 已记账`）
- 丢弃时对称撤销

### 9.4 小数血量
`智力×0.5` 会产生小数 → 写入前 `R2I(x + 0.5)` 四舍五入。

### 9.5 性能
4 英雄 × 1 次/秒 = 4 次/秒，可忽略。

### 9.6 引擎重算与自管的冲突（重要）

因为 `StrHitPointBonus = 0` 且模板血 = 0，**引擎重算血量时算出的是 0**。
所以每次属性变化，引擎会先把最大生命归 0，再由我们写回正确值 —— 这中间有一段极短窗口。

**对策**：
- 属性变化点（升级/破境/加属性）**同步调用** `Stat_Refresh`，把窗口压到同一帧
- 1 秒周期兜底任何遗漏

## 十、调用场景清单

### 10.1 必须调用的场景

| # | 场景 | 调用 | 现状 |
|---|---|---|---|
| 1 | 英雄创建完成 | `Stat_Refresh` | ✅ 已有 `V3_Init` |
| 2 | 英雄升级 | `Stat_Refresh` | ✅ 引擎事件，需挂 `EVENT_PLAYER_HERO_LEVEL` |
| 3 | 破境加属性（`V3_TierUp`） | `Stat_Refresh` | ✅ 已有触发器，需补调用 |
| 4 | 英雄复活 | `Stat_Refresh` | ✅ 已有 `V3_Death`，需补调用 |
| 5 | 1 秒周期兜底 | `Stat_Refresh` | ➡️ 待建 |
| 6 | 装备/书 直接加血 | `Stat_Mod` | ⬜ 本期先建函数，装备系统后接 |
| 7 | 装备/书 加属性 | `Stat_Refresh` | ⬜ 有属性变化就要刷 |

### 10.2 判断口诀

> **"这个改动会不会让英雄的力量/敏捷/智力，或者基础血量变化？"**
> 会 → 调 `Stat_Refresh`（属性变了）或 `Stat_Mod`（基础血量变了）
> 不会 → 不用管

### 10.3 分阶段实施

**阶段 1（现在做）**

1. ✅ 改 6 个游戏常数（`StrHitPointBonus=0` 等）
2. 改 `H000` 模板：最大生命/魔法 = 0，力量/敏捷/智力 = 10/10/10
3. 建变量：`BaseHP[4]`、`AttrHP[4]`、`ModTarget`、`ModDelta`、`TempInt`、`TempReal`
4. 建 `Stat_Refresh`（血量公式 + 钳制 + 判空）
5. 建 `Stat_Mod`（只处理血量）
6. `Stat_Refresh` 加 1 秒周期事件
7. 挂 `EVENT_PLAYER_HERO_LEVEL` 监听（升级后刷）
8. `V3_Init` 末尾调一次 `Stat_Refresh`
9. `V3_TierUp`（破境）加属性后调 `Stat_Refresh`
10. `V3_Death` 复活后调 `Stat_Refresh`
11. 建 `war3mapSkin.txt`
12. 起图验证：初始血量 = 10×2+10×1+10×0.5 = **35**

**阶段 2（做装备时）**

1. 装备拾取/丢弃/替换监听 → 调 `Stat_Mod`（加血）或 `Stat_Refresh`（加属性）
2. 防重复记账

**阶段 3（做加点/道具时）**

1. 加点界面 → 改属性后 `Stat_Refresh`
2. 属性之书 → 改属性后 `Stat_Refresh`

## 十一、已定结论汇总

| # | 项 | 决定 |
|---|---|---|
| 1 | 架构 | 血量自管（基础+属性），其余属性交给引擎 |
| 2 | 血量公式 | `BaseHP + 力量×2 + 敏捷×1 + 智力×0.5` |
| 3 | `StrHitPointBonus` | 设为 **0**（引擎不参与血量） |
| 4 | 其他 5 个常数 | Regen 0.01 / Mana 1 / Def 0 / AtkSpd 0 |
| 5 | 主属性 → 攻击 | 引擎原生 1:1，不做倍率变化 |
| 6 | 初始基础血量 | 0（模板血 0，属性 10/10/10 → 35 血） |
| 7 | 掉上限 | 直接钳制 |
| 8 | 升级重写 | 属性变化点同步刷新 + 1 秒兜底 |
| 9 | 攻击力 buff | 不使用 |
| 10 | `Stat_Mod` 字段 | **本期只有血量**，以后按需扩展 |
| 11 | 属性提示文案 | `war3mapSkin.txt` + `|n` 换行塞多条 |

## 十二、调研结论（存档）

| 主题 | 结论 |
|---|---|
| `SetUnitState(MAX_LIFE)` | 覆写语义；英雄升级会重写 → 需同步/周期刷新 |
| 主属性 → 攻击 | 引擎原生 1:1 白字；`StrAttackBonus` 仅对力量型可配 |
| 敏捷/智力 → 攻击 | 不存在对应常数，倍率锁死 1 |
| 敏捷/智力 → 生命 | 不存在对应常数，必须触发器算 |
| 力量/智力 → 回血回蓝 | 常数 `StrRegenBonus` / `IntRegenBonus` 存在 |
| `StrHitPointBonus` | 存在，但本期设为 0（血量自管） |
| hook override | 拦不到引擎内部重算函数（非 native），不采用 |
| 白字 vs 绿字 | 白字只能来自基础攻击（物编）+ 主属性；buff/技能都是绿字 |
